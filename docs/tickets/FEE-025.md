# FEE-025 MAメニューと最後に撮影した写真をPrefabで共有

- 状態：完了（2026-11-28）
- 発行日：2026-11-28
- 関連：[FEE-024](FEE-024.md)

## 決定した仕様

- 「MAメニューを更新してPrefabへ保存」を表情エディタに追加。
- アバター上のFEEから、現在のアバター・顔バリアントで写真を生成し、接続先のFEE Prefabにメニューごと保存する。
- 同じFEE Prefabを参照する改変で、最後に更新した写真・メニューを共用する。別々のFEE Prefabは別管理。
- MA Menu Itemで手動指定した画像・Noneは維持する。
- 保存先Prefabのメニューだけを更新する。配置先の位置、メッシュ割り当て、sourceAvatar等を一括Applyしない。
- 開いているシーンの同じFEE Prefabのインスタンスについて、以前のローカル生成メニューを取り除き、メニュー参照とIconの個別Overrideを共有状態へ戻す。その他のOverrideは保持。
- 既存のローカル生成・更新ボタンも維持。共有保存先のPrefabをPrefab Modeで編集中の場合は、保存して閉じるよう案内し、編集中の内容を上書きしない。
- メニュー出力済みの場合はPlay前のアバター別写真生成を省略。ビルドは保存済みメニューを使う。
- 写真生成に失敗した場合は更新を止め、保存済み画像を空画像で置き換えない。
- Prefab保存はファイルへ直接反映され、通常のシーンUndoの対象外。元の実データを自動で一括変換しない。

## 検証

- 検証用Prefabを2つ配置し、10項目成功：共有メニュー反映、旧ローカル出力の二重生成防止、手動アイコン共有、個別アバター参照と位置保持、Base写真の永続化・共有、別アバターからの最後の保存の反映、ビルド前整合性。
- 実アバターは撮影元としてのみ参照し、元のPrefab・表情設定は変更していない。
- 最終コンパイルエラー0、EditableMenuExportChecksの13項目も成功。撮影ズームを変更して画像が実際に新しくなり、両インスタンスの参照が同時に新画像へ変わることを確認。撮影元未指定時は保存済みメニューを保持。
- Nakiyaプロジェクト内パッケージへ反映済み。

## 残課題

- 別シーンで以前に明示的に保存したMA IconのPrefab OverrideはUnityの仕様で優先される。共有する場合はそのOverrideをRevertする。
