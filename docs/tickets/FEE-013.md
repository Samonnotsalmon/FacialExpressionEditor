# FEE-013 マテリアルの透明度編集でほほ染め・青ざめが黒くなる不具合

- 状態：完了（2026-11-17）
- 対象：表情編集・パーツ編集、既存クリップのビルド互換

## 原因と修正

- 実データのhohozomeとAozameは、それぞれmaterial._Color2nd.a／_Color3rd.aだけを0.6で記録していた。
- UnityのAnimationClip.SampleAnimationで、αだけのカーブは未記録RGBが0になり黒くなることを再現。編集用プレビューの部分適用ではRGBを維持するため、再生結果と食い違っていた。
- マテリアルInspectorで色・ベクトルの一成分を変更した際、同じプロパティの全成分を記録する。関係のないプロパティは追加しない。パーツの使用項目にも全成分を反映。
- ビルド時は既存の部分成分クリップにも不足成分を補完。選択したマテリアル・元FXの初期値を使い、明示済みのカーブは保持。元クリップ、マテリアル、パーツの選択設定は変更しない。

## 検証

- MaterialColorCompletionChecks：11項目成功。黒化の再現、補完後のネイティブ再生（Linear色空間を考慮）、表情／パーツ双方のRGBA、OFF時の透明度復元、既存RGBアニメーション保持、実際の2パーツのRGB=1・α=0.6、元データ不変を確認。
- MaterialInspectorChecks：表情・パーツ双方のRGBA記録とパーツ使用項目を確認。
- MaterialEditingChecks：色・数値・テクスチャ座標と初期値の回帰確認が成功。
- PartCategoryBuildChecks：検証用アバターのNDMFビルド・階層メニュー等12項目成功。Unityコンパイル・Consoleエラー0。
