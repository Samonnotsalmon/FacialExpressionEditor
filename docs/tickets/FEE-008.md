# FEE-008 生成アセットのフォルダ構成を整理する

- 状態：完了（2026-11-17）
- 発行日：2026-11-16
- 推奨順：8（初回改善の統合確認後）
- 関連・前提：[FEE-004](FEE-004.md)、[FEE-005](FEE-005.md)、[FEE-006](FEE-006.md)。既存の名前変更・非表示設定・パーツ分類を維持する。

共通方針は[チケット一覧](README.md)を参照。2026-11-17の個別指示で実装着手。

## 背景・要望

- 設定単位にデータがまとまる現在の方針を維持しつつ、普段使うPrefab・表情・パーツと、内部の設定・補正用データを分けたい。
- 2026-11-15に提案した、浅い階層で探しやすくする構成を反映するため、ユーザーからチケット発行の依頼を受けた。
- 対象はツールがAssets/FacialExpressionEditor配下などに生成する設定フォルダ。ツール自身のEditor・Runtimeなどのソース配置は対象外。

## 決定した方針

- 設定ごとのフォルダを単位としてまとめる。
- 設定フォルダの直下に導入用Prefab、Expressions、Partsを置き、よく使うものにアクセスしやすくする。
- 設定・補正用データはSettings配下へまとめる方向とする。具体的なフォルダ名は仮称で、実装時に整合性を確認する。
- 元のアバターや配布元のアニメーションなど、ツールの管理対象外のアセットは移動しない。
- 既存の参照、編集中のデータ、名前変更機能、ライブラリの非表示設定、パーツ分類・排他設定を維持する。

## 目標構成

```text
設定名/
├─ 設定名_FEE.prefab
├─ Expressions/
├─ Parts/
└─ Settings/
   ├─ 表情データ.asset
   ├─ ベース顔.asset
   ├─ Blink/
   ├─ MouthCancel/
   ├─ Overrides/
   └─ Variants/
```

存在するデータを用途別に配置する例。不要な空フォルダを作ることや、既存の個別ファイル名をこの例に合わせて変更することは要求しない。

## パーツ分類との関係

- FEE-006では「1階層・ツール内だけの分類」「実ファイルの配置は変更しない」がユーザー確認済みで、実装も完了している。
- 以前の提案例にあったParts/グループ名/は、この決定を踏まえて今回の必須範囲には含めない。
- 画面内フォルダや排他グループと実フォルダの自動連動は行わない。連動を希望する場合は別途仕様を確認し、追加チケットにする。

## 確認・検討事項

- 現在の全生成経路を確認し、上記以外の補助アセットがあれば配置先を決める。
- 既存設定にも移行を提供するか、新規作成・複製から新構成を適用するか。既存設定を移行する場合は、起動時自動処理か明示操作かを含めて決める。
- 保存先の基準を確認する。表情データ.assetをSettingsへ移した結果、ExpressionsやPartsがSettings内に生成されないようにする。
- 名前変更・複製・ライブラリ検索・クリップの管理対象判定など、現在の配置を前提とする処理への影響を確認する。
- 既存設定の移行を採用する場合、同名フォルダ・同名ファイル、移行途中の失敗、再実行の扱いを決める。

## 作業内容と確認観点

1. 最新の生成・保存・参照処理を調べ、配置先と既存データの扱いを確定する。
2. 新規設定、設定複製、表情・パーツ作成、口キャンセル、補正・バリアントなどの生成先を統一する。
3. 既存設定の扱いを決定した方式で実装する。移行を行う場合はUnityの参照を維持する方法を使い、既存アセットの上書きや管理対象外の移動を防ぐ。
4. 新規作成と複製後に目標構成になること、複製先が元設定の編集用データと独立することを確認する。
5. 保存・再読み込み後の編集、名前変更、ライブラリ表示・非表示、パーツ分類・排他動作、Prefabからの参照が維持されることを確認する。
6. 旧構成の設定が決定した互換・移行方針どおりに使えることを確認する。移行を採用した場合は再実行や名前衝突も確認する。
7. 変更に応じたコンパイル・ビルド確認と既存チェックを行い、保存場所に関する仕様書・操作説明を更新する。

## 完了記録

- 2026-11-17確認：既存設定は移動せず継続利用。新規作成・専用複製から新構成を適用する。自動移行・手動移行は実装しない。

- 決定した仕様：新規作成・複製では直下にPrefab・Expressions・Parts、Settingsに表情データ・ベース顔・Blink・MouthCancel・Overrides・Variantsを配置。必要になった分類だけ生成する。旧設定は従来の配置で継続利用し、専用複製で新構成にする。ツール内のパーツ分類とは連動しない。
- 変更内容：新旧構成を識別する保存情報と共通の設定ルート計算を追加。新規・専用複製・別ベース顔複製、表情作成・合成・リアクション取り込み、パーツ生成、補助クリップ複製、ベース顔の差し替え保存先を整理。Prefab検索・ライブラリ検索・管理対象判定・複製先計算・Inspectorの保存先表示も対応。同名の複製先は番号付きで作成し上書きしない。
- 検証結果：Unity 2022.3.22f1でコンパイル・Consoleエラー0。AssetLayoutChecks 17、AssetLayoutBuildChecks 4、SetupDuplicationChecks 19、TicketIntegrationChecks 10、PartFolderChecks 14、PartDragChecks 13の計77項目成功。実際の新規作成処理、新旧の生成先、保存再読み込み、専用複製とUndo、非表示・名前変更、パーツ分類・排他設定を確認。Core_WKアバターの検証用コピーでNDMFビルドし、FX・メニュー生成と元設定不変を確認。検証用データは削除済み。
- 残課題・関連チケット：既存アセットの移行は確認済み方針により対象外。VRChatへのアップロード・GitHub公開は未実施。
