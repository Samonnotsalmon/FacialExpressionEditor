- このチャットでは相談・仕様整理・チケット更新のみを行い、実装は別タスクで行う。
- 発行時点ではコード・実画面の調査も実装も行っていない。既存の作業指示と実装を確認してから作業する。上記は現状調査前の推奨順。
- 「背景・要望」「決定した方針」を基準にする。「検討案」は未承認であり、確定仕様として扱わない。

- 自分用のツールとして簡潔な文言と配置を重視する。起動直後のアバター選択画面に説明パネルや操作ガイドを追加しない。
- 既存の編集内容・アニメーション参照・排他動作を壊さないように変更する。
- 「確認の目安」は検証観点であり、未確定の操作方法や保存方式を確定するものではない。

## 追加・更新の運用

- 新しい独立した要望は[テンプレート](TEMPLATE.md)から次の連番で追加する。次は **FEE-029**。発行後はこの番号も更新する。
- 既存の要望への補足・方針変更は該当チケットに追記する。決定事項と提案を分け、古い案との矛盾を解消する。
- 完了済み機能への追加変更は新規チケットとし、元チケットを関連付ける。
- 新規発行時は一覧にも追加し、依存関係に応じて推奨順を調整する。IDは変更・再利用しない。
- 状態は「未着手」「作業中」「確認待ち」「完了」「保留」。確認待ち・保留では理由と再開条件を記載する。
- 作業担当は着手・完了時に状態を更新し、完了時は決定仕様、変更内容、検証結果、残課題を記録する。
- 必要な確認を行ってから完了にする。未解決の独立課題は関連チケットとして残す。
- 旧メモに仕様を重複して管理しない。
