# NSL_Facial Expression Editor 仕様

## 対象と基本方針

Unity上でVRChatアバターの表情を編集し、Modular AvatarとNDMFで適用する。
特定アバターの購入や内部構成の知識を前提としない。
元のアバターアセットは変更せず、編集用アニメーションと設定用Prefabを作成する。

## 作成・複製

- シーン上のアバター、表情を編集するメッシュ、必要な連動対象を選ぶ。
- 現在のシェイプキー値をベース顔として記録する。顔を変更して再登録する場合は新しい設定を作る。
- 初回作成は設定名のフォルダにPrefab・設定・アニメーションをまとめる。
- 専用設定への複製は名前だけを指定し、元設定フォルダの隣へ保存する。同名には番号を付ける。
- ジェスチャーと固定メニューの割り当てを維持し、表情・パーツ・補助アニメーションを複製する。
- 複製先では現在のアバターからベース顔とシェイプキーを読み直す。
- シーンでは対象の設定用Prefabを置き換える。元Prefabや他アバターは変更しない。適用はUndo／Redo対応。

## 取り込みとライブラリ

- アニメーションクリップまたはフォルダを指定して取り込む。
- 登録したフォルダとサブフォルダをライブラリに表示し、フォルダ単位で絞り込める。
- フォルダ構成を固定メニューへ自動追加しない。
- 一覧でサムネイル、使用状況、時間変化の有無を表示する。選択した動く表情を再生できる。

## 表情・パーツ編集

- 新しい表情は登録したベース顔から作成する。目口などのクリップ合成にも対応する。
- 表示名、アニメーション名、ファイル名を一致させる。
- 通常の数値編集は内蔵し、細かな時間編集は外部ツールも利用できる。
- リップシンクのメッシュはAvatar Descriptorのインスペクターで指定し、エディタからは上書きしない。
- リップシンク用としてDescriptorに設定されたシェイプキーは表情カーブから除外する。
- 新規作成、取り込み、編集、プレビュー・ビルドで除外し、元ファイルは保持する。
- 口モーフキャンセルもリップシンク用シェイプキーを操作しない。
- パーツは表情へ重ねて使用し、登録済みの排他グループを選択できる。
- マテリアルはメッシュとマテリアルを選び、シェーダー標準のインスペクターで編集する。変更項目を自動記録し、記録済み一覧は折りたたんで確認・解除できる。数値・色・ベクトル・テクスチャの位置とサイズをアニメーションへ記録する。元マテリアルは変更しない。画像の差し替えとシェーダー変更は対象外。
- パーツはONの間だけ表情より優先して上書きし、OFF時は現在の表情の値を使う。表情にマテリアル値の指定がない場合だけ初期値へ戻す。
- 排他グループでも選択中のパーツの操作対象だけを上書きする。選択していないパーツが表情の値を消すことはない。
- モーションによるパーツ停止中は上書きを解除し、復帰後はメニューで選択中のパーツだけを有効にする。

## ジェスチャー・固定メニュー

- 左右のジェスチャーを2列で表示し、それぞれ完成した表情を割り当てる。基本は右手優先。
- Fistの握り込みでは目元をベース顔から割り当て表情へ変化させる。口元は完成表情を維持する。
- 閉じ方は表情自体を編集して調整する。
- 「Base」で登録時の顔を維持できる。「固定解除」でジェスチャー制御へ戻す。瞬き・リップシンクとパーツの設定は維持する。
- ジェスチャー以外の表情は固定メニューに登録できる。フォルダによる分類に対応する。
- 瞬き・視線・リップシンク・口キャンセルの一覧は割り当て済み表情のみ表示する。
- 一覧の同じ列を上下ドラッグして連続ON／OFFできる。1回のUndoで戻せる。

## 元FX・既存メニュー

- 選択したFXレイヤーだけを生成レイヤーへ置き換える。
- 元のExpression Menu、MAの既存メニュー、既存Expression Parametersは削除しない。
- 元メニューの整理は利用者がModular Avatarで行う。旧設定のメニュー削除指定も適用しない。
- モーション連携は条件に応じて表情制御を譲り、終了後に固定表情・パーツ設定または現在のジェスチャーへ戻す。

## 瞬き・MMD・モバイル

- 瞬きクリップの指定、自動検出、シェイプキーからの生成に対応する。
- ゲーム内に瞬きOFFとMMD対応の切り替えを用意する。これらの選択は保存しない。
- MMD対応は衣装・ギミックを維持する方式を標準とし、FX全体停止を予備方式とする。
- メニューサムネイルはPC向けDXT5、Android／iOS向けASTCをビルド時に選ぶ。

## 検証

合成したテスト用アバターで、割り当て維持、編集の独立性、ベース顔の再取得、リップシンクカーブ除外、メニュー保持、非保存パラメータ、テクスチャ形式を確認する。
実アバターのビルド確認はProjectで選択したPrefabを対象に実行できる。固有の商品名や内部アセット構成を公開文書へ記載しない。

## コンタクト・PhysBoneの反応クリップ

- 元FXを残し、選択したレイヤーで使うクリップだけをビルド時に差し替える。条件・遷移・サブステートマシン・Entry/Exit・パラメータドライバー・レイヤー順は引き継ぐ。
- 反応ごとのON/OFFは元アバターの設定を使う。追加メニュー、追加の同期パラメータ、優先順位の並び替えは生成しない。
- 「反応」タブは、コンタクト・PhysBoneの入力を遷移条件・Motion Time・BlendTree等で直接参照し、顔を動かすレイヤーだけを表示する。出力パラメータの連動先はたどらず、検出済みの瞬き・口モーフキャンセルも除外する。間接パラメータだけで制御するレイヤーは対象外。
- 「複製して編集」で独立クリップを作る。指定したレイヤー内で、同じ元クリップを参照する状態・BlendTreeの枝が差し替え対象となる。同じクリップを使う別レイヤーには影響しない。
- 別クリップへの差し替えは全体の置換とする。元の耳・尻尾などのカーブを自動合成せず、必要な動きは置換後に追加する。
- Motion Time・BlendTreeの構造とパラメータは維持する。クリップは時間カーブ・明示的な0・未指定範囲を保持して複製し、余分なベース顔や全シェイプキーの値を追加しない。リップシンク保護は通常表情と共通。
- 編集するクリップが操作するメッシュ、オブジェクト、マテリアルの対象パスを編集対象へ追加する。耳・尻尾は同じ表情クリップに含まれる動きをそのまま保持し、Transformの編集対象への自動追加や別レイヤーの編集は今回は行わない。追加だけではカーブを生成しない。細かな時間編集はUnityのAnimationなど外部の編集機能を使う。
- 不要なレイヤーは「アバター設定 → 置き換える元FXレイヤー」で除外する。連動が複数レイヤーに分かれる場合は、不要な連動先も同じ一覧で選ぶ。元のメニューはModular Avatar側で整理する。
- モーション連携タブには反応と重複する元FX一覧を表示しない。以前に手動登録した簡易反応は互換性のため反応タブに残すが、新規追加の導線は設けない。

### 固定表情との関係

- 固定中だけ、反応より後ろの生成レイヤーで顔のRendererプロパティを固定表情の値にする。同じ反応クリップに含まれる耳・尻尾のTransformカーブは上書きしない。
- 顔の範囲は選択した顔メッシュで区別する。以前の固定対象外プロパティ指定は互換性のため保持するが、耳・尻尾向けの設定UIは表示しない。
- 別レイヤーに分かれた耳・尻尾の制御は元FXをそのまま使う。固定中の重み制御も追加しない。
- 固定中の復帰値が必要な場合だけ、生成クリップに不足項目を補完する。編集用クリップには保存しない。既存FXのマテリアル初期値も参照する。
- 通常時には生成した固定用レイヤーを重み0にし、元の反応同士の重なり方を維持する。モーション連携で表情を譲る間は固定用レイヤーも停止する。
- 元FXのTracking Control等のBehaviourは保持する。固定用の補助処理は顔のアニメーション値を対象とし、既存Behaviourを条件別に作り直す処理ではない。

### 対応範囲と検証

- 同名レイヤー、同期・共有ステートマシンは個別差し替え対象を安全に特定できないため、UIで理由を表示し元構成を維持する。
- 差し替え登録後に元レイヤー・元クリップがなくなった場合は、反応タブから古い登録を解除できる。ビルドは見つからない登録を無視せずエラーにする（除外するレイヤーの登録は検証対象外）。
- `Tests/ReactionChecks.cs.txt` は、複数条件、瞬き・口キャンセル・連動先・骨専用レイヤーの除外、Motion Time、BlendTree、共有クリップの独立性、固定中の顔と骨の区別、設定複製を検証する。
- 参照用アバター2体のFXで差し替えを含むビルドを確認。VRChat実機での接触・つかみ操作や他ギミックとの最終確認は別途必要。

## アニメーションの記録範囲と未指定値の扱い

この節は、取り込み・作成・編集・合成・プレビュー・ビルドを変更するときの共通判断基準とする。
方針の記載は機能の実装完了を意味しない。現状との差は末尾の「実装状況」で管理する。

### 調査から確認した構成

2026-10-15、開発プロジェクトへ取り込み済みのPrefabが参照するFXと追加FXのアニメーションを読み取った。
以下は読み取れた構造の分類であり、全構成の実行時動作を確認したという意味ではない。
商品名、クリップ名、パラメータ名、アセットパス、元データの内容は掲載しない。

- カーブを持たないクリップと、Motionが未設定のステートが存在する。
- 少数のシェイプキーだけを持つクリップと、多数をまとめて指定するクリップが混在する。
- 値0のカーブを明示的に持つクリップが存在する。
- 時間で値が変わるシェイプキーカーブが存在する。
- マテリアルやTransformも操作するクリップが存在する。

クリップ名やカーブ数だけから「完全な表情」「部分表情」「リセット用」と断定しない。
使用するステート、遷移、レイヤー、入力パラメータも確認する。

### 区別する状態

| 状態 | 意味 | 編集・生成での扱い |
| --- | --- | --- |
| 未指定 | そのプロパティのカーブがない | このクリップには値の指定がない。勝手に0や現在値を記録しない |
| 明示的な0 | カーブが存在し、0を指定している | 意図された上書きとして保持する。未指定への変換には明示的な解除操作が必要 |
| 明示的な非0 | カーブが存在し、その値を指定している | 指定値として保持する。ベース顔と同値でも、必要な上書きなら削除しない |
| 時間変化 | 時刻・値・補間を持つカーブ | 始点や終点だけを見て定数化・削除しない |
| ベース顔の補正 | 登録した顔に合わせるための指定 | 対象と適用方針を管理し、クリップの未指定とは分けて扱う |
| 実行用の復元値 | 遷移後の残留を防ぐために生成する値 | 保存用の表情へ混ぜず、必要な操作範囲・状態・レイヤーだけへ生成する |

「0へ変更」は値の記録、「この表情では操作しない」はカーブの解除として別操作にする。
ベース顔や表情のために必要な0も保持する。値から指定の理由を推測して削除しない。
原本に0のカーブがあることは確認できても、作者の意図までは自動判定できない。
利用者が指定したベース顔補正によって最終値を変える処理と、原本の指定を消す処理は別である。補正対象では、元の明示値と補正後の値を区別して追跡する。

### Emptyと部分的な表情

- Emptyは、編集対象への値の指定を持たない作成方法として用意する。全シェイプキーを0にする方法ではない。
- Motion未設定と空のAnimationClipは別の状態として取り込み時に区別する。
- 顔のシェイプキーカーブがなくても、マテリアル、オブジェクト、ボーン、イベントなどがあればクリップ全体は空ではない。
- 空のクリップでも、Write Defaults、レイヤーの重み、StateMachineBehaviourなどにより実行時に影響が出る可能性がある。「Emptyだから何も上書きしない」と保証しない。
- 部分的な表情は、操作対象に指定されたプロパティだけを記録する。目だけなら口、口だけなら目を自動追加しない。
- ベース顔から作る通常の導線は維持する。Empty／操作対象だけの作成は追加の選択肢として扱い、既存設定を自動変換しない。
- Emptyで開始したデータを、ベース顔補正の処理で暗黙に全顔クリップへ変えない。ベース顔を参照して表示することと、カーブを書き出すことを分離する。

### ベース顔と保存用クリップ

登録時の顔を再現するためのスナップショットは、広い範囲の値を保持してよい。
ただし、その全値を通常の表情・パーツへ自動で書き出す根拠にはしない。
「Base」で顔そのものを固定する用途と、部分表情を重ねる用途を区別する。

保存するカーブには、少なくとも取り込み由来、利用者の編集、ベース顔の適用という理由を追える設計を目指す。
生成時に追加する復元値は別に追跡し、編集用クリップへ逆流させない。
現在値と違うかどうかだけでは、明示的な固定値や0の必要性を判定しない。

編集UIでは次を区別して表示・操作できるようにする。

- この表情が記録している項目。
- 参照として表示しているベース顔・下位制御の値。
- 記録値を0にする操作。
- 記録そのものを解除する操作。

### 取り込み・合成・プレビュー・ビルドの責務

| 段階 | 守ること |
| --- | --- |
| 取り込み | 原本を保持し、既存カーブと未指定範囲を読み取る。全シェイプキーの値埋めや0カーブの一括削除をしない |
| 合成 | 選択した範囲のカーブを合成する。未指定を0として扱わない。同じ対象が競合した場合だけ優先元を明示する |
| 編集 | 変更・記録指定した項目を対象にする。ベース顔と同値、または0でも明示記録できるようにする |
| プレビュー | ベース顔へ重ねて見せても、その表示値を保存カーブへ自動変換しない。切り替え時は前のプレビューの変更を解除する |
| ビルド | その制御が担当する範囲だけを生成する。復元が必要なら、担当範囲と復帰先を確認して生成クリップに限定する |

リップシンクなど既に定めた操作禁止範囲は別途守る。保護対象の除外と、未指定を維持する処理を混同しない。
Transformなどの連動対象も、元クリップのバインディングから候補に追加し、一覧で確認・除外できる方針とする。
「編集対象として参照できる」ことは「その対象の全プロパティを毎回記録する」ことを意味しない。

### 上書きと復帰の例

以下の値は説明用の仮の値であり、特定のアセットに由来しない。

- 表情があるシェイプキーを30に指定し、パーツが80に指定する場合、パーツOFFは30、ONは80、再びOFFは現在の表情の値に戻る。
- パーツON中に表情が30から50へ切り替わった場合、OFF後は30ではなく50へ戻る。
- 表情が0を明示していれば、パーツOFF後はその0を使う。
- 表情が未指定なら、定めたベース顔・下位制御・復元処理へ任せる。未指定を一律0に変換しない。
- 排他グループで別パーツを選んでも、そのパーツが担当しない値は現在の表情へ任せる。
- 同じ考え方をマテリアル、オブジェクトのON/OFF、ボーンの動きにも適用する。ただし値の表現や補間方法は各種別に合わせる。

Write DefaultsのON/OFFだけでこの優先順位を保証しない。クリップ、ステート、レイヤー重み、既存制御を組み合わせて検証する。

### 今後の変更で確認する項目

1. Emptyの保存データに、未選択のシェイプキー・現在値・0が追加されていない。
2. 部分表情で、対象外の目・口・パーツ・連動対象を操作しない。
3. 明示的な0と非0が保存・再読込・複製・合成後も残る。解除操作ではカーブがなくなる。
4. 始点と終点が0でも、途中に変化があるカーブを消さない。キーの補間も保持する。
5. ベース顔の表示・再取得だけで、保存用クリップの記録対象が増えない。
6. パーツOFF→ON→OFFと、ON中の表情変更で、現在の表情へ復帰する。
7. 排他切り替え、モーション停止・復帰後に未選択パーツが上書きしない。
8. 一部マテリアルの既定値を、異なる既定値の別マテリアルへ誤って流用しない。
9. 原本のクリップ・マテリアルを変更しない。
10. 空のクリップとMotion未設定を、それぞれステートとレイヤーを含めて検証する。

最初は合成した最小構成で期待値とバインディング集合を確認し、その後に利用者が指定した実アバターで確認する。
画像が同じという理由だけでカーブの指定範囲が同じとは判断しない。公開する結果は構成の特徴へ一般化する。

### 実装状況と修正候補

| 箇所 | 現状・今後の扱い |
| --- | --- |
| `ExpressionSetUtility.NewExpressionSource.Empty` | 内部の作成方法として存在する。通常UIはベース顔からの作成が中心で、Emptyの選択導線は今後整備する |
| `ExpressionSetUtility.WriteCurrentFace` | 新規作成では、保存済みベース顔の非0値と、有効な補正項目（明示的な0を含む）だけを記録する。無関係な0や他の表情だけが使う項目は追加しない |
| `BaseFaceProcessor.Apply` | 既存方式の互換性のため維持する。新規作成・表情複製では必要なベース顔をクリップへ記録済みとして扱い、プレビュー・ビルドで再補正しない。以後の値調整はクリップを直接編集する |
| `PreviewClips.ForBaseFace` | 顔を固定するためのスナップショット出力。通常表情やパーツへそのまま転用しない |
| `PreviewClips.ForPart` / `ExpressionClipBuilder.BuildPart` | 選択したプロパティだけを出力する経路がある。今後もこの範囲指定を維持する |
| `ExpressionSetUtility.MakePartClipEditable` | パーツを複製する際も選択したプロパティだけを残す。ベース顔は加えず、選択項目の0や時間変化は保持する。新規パーツは空の状態から開始する |
| `FillMissingWithDefaults` / `FillMissingMaterialDefaults` | 実行用の補完処理。利用箇所ごとに担当範囲・優先順位・復帰先を検証し、保存データの一括補完には使わない |
| パーツの上書き | OFF時のレイヤー重み0、ON時の上書き、現在の表情への復帰を実装済み。任意の空クリップ全般の動作保証とは区別する |
| 反応クリップと連動対象の自動追加 | 元FXを保持したクリップ差し替えと編集対象の追加を実装。対象パスの追加ではカーブを増やさない。対応範囲は「コンタクト・PhysBoneの反応クリップ」を参照 |

既存クリップのカーブを一括削除する移行は行わない。広く記録された値が意図的なリセットかどうかを自動で断定せず、対象・差分を確認できる移行方法を別途用意する。

表情の複製は、元のカーブ（明示的な0や時間変化を含む）と必要な顔補正を引き継ぐ。複製元に既にある0を自動で削除する機能ではない。Emptyで作成したクリップにはベース顔も自動追加しない。設定全体の複製では既存クリップの編集方式も引き継ぎ、既存データを一括変換しない。

`Tests/SparseExpressionChecks.cs.txt` で、新規表情の記録範囲、明示的な0、直接編集後の再補正防止、複製、Empty、パーツの選択範囲と原本保持を検証する。
